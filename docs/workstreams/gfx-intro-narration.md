# Graphics: intro narration (pre-rendered text crawl before the title)

## Goal

Replace the pre-drawn Japanese narration shown after power-on (text over a
cloud background, before the title screen) with original English narration
that looks like the original lettering: same place, size and rows, the
original palette, the same white strokes with a thin blue outline, and every
other pixel unchanged. Round 1 located and decoded the data and planned the
replacement; round 2 (task `gfx-intro`) built the graphics target.

### Style: the original lettering, measured

The 15 original lines were decoded locally (never committed) and measured
(scratch `r2-gfx2-intro\analyze_orig.py`, `style_stats.py`):

| Property | Original | English (`intro.py`) |
|---|---|---|
| colors | 0 transparent, 1 white strokes, 3 blue outline; color 2 unused | the same indices; the palette at `0x290F55` is kept (no palette write) |
| rows of the 144 x 16 line | ink rows 4-14 in every line, outline rows 3-15 | `title16` glyph row 0 on line row 4 (`TOP`): ink rows 4-14 (4-12 without descenders), outline rows 3-15 |
| outline | 1 px on the 4 orthogonal neighbors: 2,193 of the 2,357 positions that touch the ink only diagonally are empty; the other 164 are scattered single pixels | exactly the 4-neighbor ring (`Style(ink=1, outline=3, outline8=False)`) |
| strokes | 1 px (74-90 % of horizontal ink runs are 1 px) | 1 px (80-84 %) |
| letter height | 11 rows (full-height glyphs) | capitals 9 rows, x-height 6, descenders 2 (11 rows in all) |
| horizontal placement | each line centered in 144 px (centers 70.5-72.0) | centered (`render_box`, left-biased by half a pixel: centers 71.0-71.5) |
| shadow, glow, texture | none (flat white) | none |

Round 1 recommended an 8-neighbor outline for legibility over bright
clouds. Next to the original it is visibly heavier, so the target uses the
original's 4-neighbor ring; in the harness the English reads as well over
the clouds as the original lettering does. `STYLE` in `intro.py` is the one
place to change it. The round-2 font notes (`gfx-fonts.md`) put glyph row 0
on line row 3; the target uses row 4, the rows of the original lettering.

### Modes (as built)

* **In place** (the original structure 6/6/3): line n goes to `0x290F5D +
  0x240 * n` as 36 tiles (the top 18 cells, then the bottom 18; `tiles_lines`).
  No hooks and no new ROM; the original table and map stay in use.
  `Result.allow` is `0x290F5D`-`0x29311C`.
* **Relocated** (any other structure): lines 0-14 are written in place; the
  generated `build/gfx/intro/intro.asm` holds `.org GFX_INTRO`, the line table
  (`intro_table`), the narration map (`intro_map`) and the bitmaps of lines 15
  and up (`intro_line15`...), plus three operand hooks:

  | Operand | Instruction | Original value | New |
  |---|---|---|---|
  | `0x28D0A3` (4 bytes) | script `stv32` at `0x28D0A2`: line table -> task var 0x28 | `0x28D1EA` | `intro_table` |
  | `0x28D0B7` (2 bytes) | `cp.w WA, 0x228` at `0x28D0B5`: end of the crawl | 552 | `intro_end_pos` |
  | `0x28D0E2` (4 bytes) | `ld.l XIY, 0x293DDD` at `0x28D0E1`: narration map | `0x293DDD` | `intro_map` |

  The test checks these instructions in the original ROM. Size in
  `GFX_INTRO`: 7 bytes per line + 2, 40 bytes per map row (end / 8 + 5 rows)
  and 576 bytes per line beyond 15; 4,673 bytes for the 17-line test; up to
  33 lines fit in the 16 KB.
* **Layout rules** (class `Layout`): triggers 24 px apart in a paragraph and
  64 px between paragraphs, line n in VRAM slot n mod 5, end = last trigger +
  136, map rows = end / 8 + 1 + 4 blank rows (as the original). `check_slots`
  refuses a line that reloads a slot less than 120 px after the slot's
  previous line (with these constants it never happens: 5 lines x 24 px =
  120). Each extra line makes the crawl 24 px, about 4.3 s, longer.

### Round 1: what the screen is

The narration is one slow vertical text crawl. After the SNK logo (crawl
position 0 at frame ~294 from power-on) white lines with a blue outline scroll
upward over a static cloud picture, inside a window 160 x 104 px (screen rows
24-127; rows above and below are black). 15 lines in three paragraphs
(6 + 6 + 3 lines), line pitch 24 px, paragraph gap 64 px, speed 0.0928 px per
frame (~5.6 px/s; a line takes ~21 s from entering at the bottom of the window to
leaving at the top). At scroll position 552 the script fades to the title screen
(~frame 6280). A skips: a short fade (A at frame 1000 gives the title at frame
~1060). Without input the attract loop returns to the SNK logo and the crawl
after a while on the title screen.

### Round 1: data (CPU addresses, original ROM)

| What | Address | Size | Format |
|---|---|---|---|
| Text palette (scroll plane 1, palette 0) | `0x290F55` | 8 bytes | 4 color words: transparent, white (strokes), light blue (unused), blue (outline) |
| Line bitmaps | `0x290F5D` + `0x240 * n`, n = 0..14 | 15 x 576 bytes (`0x290F5D`-`0x29311C`) | uncompressed 2bpp tiles; each line is 144 x 16 px = 36 tiles: tiles 0-17 top row, 18-35 bottom row (left to right) |
| Line table | `0x28D1EA` | 15 x 7 bytes + end mark `FFFF` (to `0x28D254`) | `[u16 scroll trigger][u16 VRAM dest][u24 ROM source]` |
| Narration tile map | `0x293DDD` | 74 rows x 20 entries x 2 bytes (2,960 bytes, to `0x29496C`) | one map row per 8 px of scroll; columns 0 and 19 blank (tile 0), columns 1-18 = the 18 tiles of a line's top or bottom row; palette 0, no flips |
| Cloud palettes | `0x29311D` | 16 bytes | 2 palettes for plane 2; word 0 (dark blue sky) is also copied to the background color `0x83E0` |
| Cloud tiles | `0x29312D` | 203 tiles (3,248 bytes) | raw, to VRAM tiles `0xB5`-`0x17F` (two copies: 100 + 103 tiles) |
| Cloud map | `0x29496D` | 2-byte header (20 columns, 19 rows) + 380 entries | plane 2 at `0x9800`, static; no text in the clouds |

### Round 1: code

* Entry: native code at `0x28C73C` clears `0x6084` and sets task 0's script to
  `0x28D025`: spawn task 1 (`0x28D255`), a sound command (`snd2`), display off,
  then the setup below. Task 1 waits 30 frames, then polls newly pressed buttons every
  frame (`0x201B37`, mask `0x70` = A, B or Option); on a press it sets `0x6084` = 1
  and runs `0x28D17D` (fade, display off, main state -> `0x28C6C7`, window back
  to full screen): the skip.
* Setup, native code at `0x28D030`: window x 0, y 24, w 160, h 104; clears RAM
  `0x6086`-`0x6095`; then script bytecode at `0x28D05B`: clear the plane 1 map
  (20 x 32 entries), cloud map to `0x9800` (`gfxfe 0x29496D`), blank tile 0, text
  palette `0x290F55` -> `0x8280`, cloud palettes `0x29311D` -> `0x8300` and
  `0x83E0`, cloud tiles; display on; then three task variables:
  `stv32 0xFFFFE840 -> var 0x20` (scroll position, 16.16 fixed point, just below 0
  so the first frame crosses 0), `stv32 0x17C0 -> var 0x24` (speed),
  `stv32 0x28D1EA -> var 0x28` (line table pointer), and the per-frame native loop.
* Per-frame loop at `0x28D0AC`: if position >= `0x228` (552) continue with the
  script at `0x28D137` (fade, title). Add the speed; low byte of the position ->
  `0x456D` (plane 1 scroll Y shadow, copied to `0x8033` in VBlank). When the
  position enters a new 8 px row, copy map row `pos/8` (20 entries from
  `0x293DDD + 40 * (pos/8)`) to plane 1 row `(16 + pos/8) mod 32` (just below the
  window) with `0x2009F4`. Then, for every table record whose trigger <= position,
  queue a VRAM transfer of `0x120` words (36 tiles) from the source to the VRAM
  dest (`0x200194`, done in VBlank) and advance the table pointer.
* VRAM: five 36-tile slots used round-robin, line n in slot n mod 5:
  `0xA010` / `0xA250` / `0xA490` / `0xA6D0` / `0xA910` (tiles `0x01`, `0x25`,
  `0x49`, `0x6D`, `0x91`; 180 tiles). A line leaves the window 120 px after its
  trigger, so a slot can be reloaded when trigger(n+5) - trigger(n) >= 120, which
  a 24 px pitch meets exactly. Tiles `0x180`-`0x1FF` are unused during the crawl
  (room for 3 more slots); no sprites.
* Normal end (`0x28D137`): if `0x6084` is set (skip in progress) stop, else the
  script at `0x28D14C`: kill task 1, fade (`0x28D18E`: copies the current
  palettes from VRAM `0x8280` (4 words), `0x8300` (8 words) and `0x83E0` to RAM
  `0x6086` and fades them in `0x20` steps), display off, main state -> `0x28C6F4`
  (title). The fade starts from whatever is in VRAM, so any palette values work.

## How to test / reproduce

Shorthand: `H` = `scratchpad\snap3\ngp_harness.exe` (set `NGP_HARNESS` to it
for `tools.gfx.harness`), `SNAP` = `scratchpad\snap3\ogre_en.ngc`. Use a fresh
copy for every apply (applying twice is refused).

    python -m tools.gfx.intro fit                               # widths, structure, mode, layout
    python -m tools.gfx.test_intro rom/baserom.ngc              # 12 tests
    python -m tools.gfx.apply SNAP t.ngc --target intro         # in-place test ROM

The crawl recipe, with a reference run on the snapshot for the screen diff
(the dump frames are the shot frames, so every shot is checked against its
crawl position):

    python -m tools.gfx.harness run t.ngc --frames 6500 --shot-every 300 --shot 6450 --vram 300,600,...,6300,6450 --out run_t
    python -m tools.gfx.harness run SNAP  --frames 6500 --shot-every 300 --shot 6450 --vram 300,600,...,6300,6450 --out run_ref
    python -m tools.gfx.intro check t.ngc run_t --ref run_ref --expect default
    python -m tools.gfx.harness sheet run_t 300 6500 300 --cols 6

Skip: run both ROMs with `--frames 1100 --input 1000:A:2 --shot 1080`, then
`python -m tools.gfx.harness diff` on the two `frame_01080.png` (0 pixels).

Relocated layout (scratch only): write a text with another structure, then

    python -m tools.gfx.intro fit TEXT
    python -m tools.gfx.intro testrom SNAP tr.ngc --text TEXT    # work folder build/gfx/intro-test/
    python -m tools.gfx.harness run tr.ngc --frames 7900 --shot-every 300 --vram 100,200,...,7800 --out run_tr
    python -m tools.gfx.intro check tr.ngc run_tr

Review sheets (local only; they show the original lettering):

    python -m tools.gfx.intro compare rom/baserom.ngc OUTDIR     # each original line next to ours, 1x and 3x
    python -m tools.gfx.intro decode t.ngc OUTDIR                # the lines a ROM shows
    python -m tools.gfx.intro preview OUTDIR                     # our lines only, preview colours

Scratch tools (`r2-gfx2-intro\`): `analyze_orig.py` and `style_stats.py`
(measurements of the original lettering and of ours), `style_cmp.py` (4- and
8-neighbor outlines next to the original), `pairs.py` (side-by-side screens
of two runs), `zoom.py`, `diagpat.py`, `reloc17.txt`.
